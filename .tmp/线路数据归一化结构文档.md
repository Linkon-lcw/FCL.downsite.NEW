# 线路数据归一化结构文档

## 概述

本文档描述 FCL 下载站中，经过 `adaptDownloadData()` 适配器处理后的**归一化数据结构**。归一化后的数据不再依赖 `apiVer` 字段，view 层和 controller 层可以统一消费，无需感知具体下载站（线路）的原始格式差异。

---

## 节点类型

归一化后的数据由两种节点类型组成：

| 类型 | 用途 | 渲染方式 |
|------|------|----------|
| **分组节点** | 选择器中的可选项（如软件名、版本号） | `<select>` 下拉框 |
| **下载叶子节点** | 最终可下载的文件 | `<table>` 表格 |

---

## 一、分组节点（Group Node）

分组节点用于构建多级选择器树。用户逐级选择后，最终到达下载叶子节点。

### 完整字段

| 键 | 类型 | 必填 | 说明 |
|----|------|------|------|
| `name` | `string` | **是** | 该分组在 UI 中的显示名称（如 `"Fold Craft Launcher"`、`"v1.2.3"`、`"线路1"` 等） |
| `default` | `boolean` | 否 | 是否为该级别的默认选中项。选择器渲染时会自动选中 `default === true` 的项；若没有默认项则选中第一个 |
| `description` | `string` | 否 | 该分组的描述文本，展示在选择框下方的 `.description` 区域。默认为纯文本，除非配合 `descriptionFormat` 使用 |
| `descriptionUrl` | `string` | 否 | 远程描述文本的 URL。controller 会通过 `loadDescription()` 异步拉取并渲染到描述区域。与 `description` 互斥（优先使用远程） |
| `descriptionFormat` | `string` | 否 | 描述内容的格式。仅支持 `"html"`（走 DOMPurify 净化后渲染），其他值或不设置则按纯文本处理 |
| `children` | `Array<GroupNode\|LeafNode>` | 否 | 子节点列表。选择该项后，controller 递归渲染下一级。与 `nextUrl`、`items` 互斥 |
| `items` | `Array<GroupNode\|LeafNode>` | 否 | `children` 的别名，语义相同。controller 内部统一按 `children` 处理 |
| `nextUrl` | `string` | 否 | 外部镜像 API 的请求地址。选择该项后，controller 会发起 HTTP 请求获取下级数据，再经 adapter 归一化。与 `children`/`items` 互斥 |
| `apiVersion` | `string` | 否 | 指定该节点的适配器协议名（如 `"fengyuan"`、`"Lemwood"` 等）。仅在 `children`/`items` 内联数据需要归一化时使用，或与 `nextUrl` 配合标记远程协议 |
| `sourceName` | `string` | 否 | 线路的人类可读名称，会向下传递为所有叶子节点的 `source` 字段。若不设置则回退为 `name` |
| `random` | `boolean` | 否 | 是否对子节点执行随机默认选择。设为 `true` 时，controller 会调用 `randomlySelectDefault()` 随机标记一个子节点为 `default` |
| `filter` | `Array<string>` | 否 | 下载 URL 的正则白名单数组。匹配任一正则的 URL 才会默认显示；未匹配的会被折叠隐藏（用户可手动展开）。子级可覆盖父级规则 |
| `nameIsSoftware` | `boolean` | 否 | 标记该节点的 `name` 即为软件名。controller 会将其存入 `softwareName` 变量，供后续 `loadDownloadNodes()` 调用 GitHub API 获取最新版本标签 |
| `notJoinRandom` | `boolean` | 否 | 该节点不参与随机默认选择。`randomlySelectDefault()` 会跳过此项 |

### 典型示例

```json
{
  "name": "Fold Craft Launcher",
  "nameIsSoftware": true,
  "random": true,
  "children": [
    {
      "name": "线路2",
      "sourceName": "线路2",
      "nextUrl": "https://fyhub.cn/api/public/v1/projects/FoldCraftLauncher/assets",
      "apiVersion": "fengyuan"
    },
    {
      "name": "线路5",
      "sourceName": "线路5",
      "nextUrl": "https://fcl.switch.api.072211.xyz/api/releases?owner=FCL-Team&repo=FoldCraftLauncher&versions=20",
      "apiVersion": "Linkong"
    }
  ]
}
```

## 二、下载叶子节点（Download Leaf Node）

下载叶子节点是归一化管线的最终产物，直接渲染为下载表格中的一行。**所有字段由 `normalizeDownloadItem()` 函数统一生成**，view 层只认识这些字段。

### 完整字段

| 键 | 类型 | 必填 | 说明 |
|----|------|------|------|
| `name` | `string` | **是** | 下载文件的显示名称。从原始数据的 `name` 或 `file_name` 字段提取。通常为文件名（如 `"FCL-1.2.3-arm64-v8a.apk"`） |
| `version` | `string` | 否 | 该下载项所属的版本号。由父级分组节点传入，用于展示或后续分析扩展。在纯文件列表（如 cxsjmc）中可能为空 |
| `architecture` | `string` | 否 | CPU 架构标识。优先使用线路显式提供的值（如 `"arm64-v8a"`、`"x86_64"`），若为空则由 `inferArchitecture()` 从文件名/URL 推断。可识别的架构包括：`arm64-v8a`、`armeabi-v7a`、`x86_64`、`x86`、`all` |
| `size` | `number\|null` | 否 | 文件大小（字节）。从原始数据的 `size` 或 `size_bytes` 字段提取。`null` 表示未知大小。UI 中通过 `formatBytes()` 格式化为人类可读形式（如 `"12.5 MiB"`），单位采用二进制制式（B/KiB/MiB/GiB/TiB） |
| `description` | `string` | 否 | 描述信息。优先为正常描述文本，若下载项不可用则可能为 `unavailable_reason`（不可用原因）。在表格中显示在"描述"列 |
| `downloadUrl` | `string` | **是** | 最终下载地址。**必须是 `http://` 或 `https://` 协议的绝对 URL**，否则会被 `isSafeNavigationUrl()` 过滤掉。由各 adapter 从原始字段（`downloadUrl`、`url`、`link`、`download_link`、`download_path`）拼接生成 |
| `available` | `boolean` | **是** | 该下载项是否可用。默认为 `true`。若线路明确标记为 `false`，下载按钮会显示"暂不可用"并阻止点击跳转，但保留行信息供用户查看 |
| `source` | `string` | **是** | 所属线路的人类可读名称（如 `"线路2"`、`"线路5"`）。由 context 中的 `source` 字段传入，用于追踪下载来源 |

### 典型示例

```json
{
  "name": "FCL-1.2.3-arm64-v8a.apk",
  "version": "v1.2.3",
  "architecture": "arm64-v8a",
  "size": 15728640,
  "description": "",
  "downloadUrl": "https://fyhub.cn/api/public/v1/projects/FoldCraftLauncher/assets/FCL-1.2.3-arm64-v8a.apk",
  "available": true,
  "source": "线路2"
}
```

## 三、数据流转全链路

```
data/mirror.json (线路配置: id, name, baseUrl, apiVer, contributeId)
       │
       ▼
data/software/{id}/detail.json (软件配置: download[{mirrorId, key}])
       │
       ▼
downloadController.js
  ├── 根据 mirrorId 查 mirror.json 获取 apiVer、baseUrl、name
  ├── 拼接 nextUrl = baseUrl + key
  └── 构造根级分组节点 { name, sourceName, nextUrl, apiVersion }
       │
       ▼
downloadSelectorController.js
  ├── 用户选择线路 → 发起 HTTP GET nextUrl
  │     │
  │     ▼
  │   downloadRepository.js
  │     ├── getJSON(nextUrl) → payload
  │     ├── getLatestVersion() → GitHub API (仅 Way2old/frostlynx)
  │     └── adaptDownloadData(payload, apiVersion, context)
  │           │
  │           ▼
  │         adapters/download/index.js
  │           └── ADAPTERS.get(apiVer)(payload, context)
  │                 │
  │                 ├── adaptFengyuan()   → { data: { assets: [...] } }
  │                 ├── adaptLinkong()    → { releases: [{ version, assets }] }
  │                 ├── adaptLemwood()    → { data: [{ name, assets }] } 或数组
  │                 ├── adaptFrostlynx()  → { versions: { [version]: asset[] } }
  │                 ├── adaptCxsjmc()     → 直接文件数组
  │                 ├── adaptWay2old()    → { type: "directory"/"file", children }
  │                 └── adaptPlain()      → 兼容旧格式 children/items/数组
  │                       │
  │                       ▼
  │                     normalizeDownloadItem(item, source, version)
  │                       └── 输出归一化叶子节点
  │
  └── 渲染归一化节点到 selectorView
        ├── 分组节点 → renderSelect() → <select> 下拉框
        └── 叶子节点 → renderDownloads() → <table> 表格
```

## 四、各适配器的原始格式 → 归一化映射

| 适配器 | apiVer | 原始格式 | 分组依据 | 叶子字段映射 |
|--------|--------|----------|----------|-------------|
| **fengyuan** | `"fengyuan"` | `{ data: { assets: [{ version, file_name, size, download_path, architecture }] } }` | 按 `version` 分组，版本降序排列 | `downloadUrl` ← `new URL(download_path, baseUrl)` |
| **Linkong** | `"Linkong"` | `{ releases: [{ version, assets: [{ name, size, download_url }] }], owner, repo }` | 每个 `release` 为一个分组 | `downloadUrl` ← `wdfDownUrl()` 拼接代理地址 |
| **Lemwood** | `"Lemwood"` | `{ data: [{ name/tag_name, assets: [{ name, size, downloadUrl }] }] }` 或直接数组 | 每个 release 为一个分组 | `downloadUrl` ← `asset.downloadUrl` |
| **LemwoodLatest** | `"LemwoodLatest"` | 同 Lemwood | 同 Lemwood，但仅保留第一个 release（`latestOnly: true`） | 同 Lemwood |
| **frostlynx** | `"frostlynx"` | `{ versions: { "v1.0": [{ name, url, size }], "v2.0": [...] } }` | 每个版本键为一个分组 | `downloadUrl` ← `item.url` |
| **cxsjmc** | `"cxsjmc"` | `[{ name, url, arch, size }]`（扁平数组） | 无分组，直接叶子列表 | `downloadUrl` ← `item.url` |
| **Way2old** | `"Way2old"` | `{ type: "directory", name, children: [...] }` 递归树 | `type: "directory"` 为分组 | `downloadUrl` ← `item.url` |
| **plain** | 无 / 未登记 | `[{ name, url, children }]` 或 `{ items/children: [...] }` | 保留已有 `children` 层级 | `downloadUrl` ← `item.url\|downloadUrl\|link\|download_link` |

## 五、辅助字段速查

以下字段存在于数据流中但不属于归一化叶子节点，仅供 controller 和 selector 中间层使用：

| 字段 | 所在层级 | 说明 |
|------|----------|------|
| `apiVersion` | 分组节点 | 用于指定 adapter 协议，controller 消费后不传递给 view |
| `nextUrl` | 分组节点 | 远程数据请求地址，controller 消费后不传递给 view |
| `sourceName` | 分组节点 | 线路显示名，向下传递为叶子节点的 `source` |
| `nameIsSoftware` | 分组节点 | 标记软件名，controller 用于 GitHub API 查询 |
| `random` | 分组节点 | 是否随机默认选择，controller 消费后不传递给 view |
| `filter` | 分组节点 | URL 正则白名单，传递给 view 用于表格行过滤 |
| `descriptionUrl` | 分组节点 | 远程描述地址，controller 异步拉取并渲染 |
| `descriptionFormat` | 分组节点 | 描述格式标记（`"html"` 或纯文本） |
| `notJoinRandom` | 分组/叶子节点 | 不参与随机默认选择，`randomlySelectDefault()` 跳过 |
| `matchedArchitecture` | 外部参数 | 用户设备的 CPU 架构，由 `detectSystemInfo()` 检测，view 用于绿色高亮推荐行 |

---

## 六、关键约束

1. **叶子节点 `downloadUrl` 必须是 `http://` 或 `https://` 绝对 URL**，否则会被 `isSafeNavigationUrl()` 过滤掉，不生成下载按钮。
2. **`available: false` 的项不会被移除**，而是显示"暂不可用"按钮并阻止跳转，确保用户仍能看到该线路提供的内容。
3. **`architecture` 为空时由 `inferArchitecture()` 自动推断**。推断优先级：显式字段 > 文件名/URL 正则匹配 > 特殊规则（如 ZalithLauncher → `all`）。
4. **`filter` 未命中不会删除行**，而是用 CSS 类 `.xf-filter-hidden` 隐藏，用户可点击按钮展开。
5. **所有 adapter 都是纯函数**，不发起网络请求。网络请求由 `downloadRepository.js` 统一管理。
6. **新增线路只需**：创建 `js/adapters/download/新线路.js`（导出 `adaptXxx` 函数），在 `index.js` 的 `ADAPTERS` Map 中登记 `apiVer`，在 `data/mirror.json` 中添加线路配置。无需修改 controller 或 view。
